[Critical] Neighbor_BICLR.m:44 — Clustering8Measure 参数顺序错误
------------------------------------------------------------------------
问题描述：res_neighbor = Clustering8Measure(Y, label_neighbor); 将真实标签 Y 作为第一个参数，
         预测标签作为第二个参数。但 Neighbor.m:30 使用 Clustering8Measure(label_neighbor, Y) 顺序相反。
依据：Clustering8Measure.m 内部 bestMap(Y, predY) 和 ACC 计算逻辑表明第一个参数应为预测标签。
修正建议：改为 res_neighbor = Clustering8Measure(label_neighbor, Y);

[Critical] demo.m:30 — Neighbor 调用缺少 randomSeed，结果不可复现
------------------------------------------------------------------------
问题描述：Neighbor(X{iv},Y) 未传入第三个参数 options。Neighbor.m 将 preOptions.randomSeed 设为 []，
         传入 Pre_HBNC 后 ~isempty(options.randomSeed) 为 false，不设置随机种子。
影响：原始 demo 的锚点生成不可复现，每次运行可能产生不同结果。
修正建议：传入带 randomSeed 的 options 结构体。

[Critical] demo.m:9 — 硬编码错误路径
------------------------------------------------------------------------
问题描述：dsPath = '...\3AMVC\dataset\'; 使用 ... 作为路径前缀，MATLAB 中这不是合法的相对路径。
依据：demo_biclr.m 使用 fileparts(mfilename('fullpath')) 动态获取路径，是正确做法。
修正建议：使用动态路径获取。

[Warning] Impro_HBNC.m:100 — object_othersMean 可能计算错误
------------------------------------------------------------------------
问题描述：object_othersMean = mean(object(object~=object_max)); 当 object 中有多个元素等于
         object_max 时，所有等于最大值的元素都被排除。
影响：若多个簇 SSE 相同且均为最大值，收敛条件判断会偏离预期。
修正建议：只排除一个最大值元素。
  [~, maxIdx] = max(object);
  object_othersMean = mean(object(setdiff(1:numel(object), maxIdx)));

[Warning] Impro_HBNC.m:103 — 收敛条件使用硬编码魔法数字
------------------------------------------------------------------------
问题描述：if sum(label==class_max)<n/50 — 当最大 SSE 簇的样本数少于总样本的 2% 时立即停止。
         缺乏文档说明或参数化。
修正建议：至少在注释中说明该阈值的含义和来源，或将其提取为可配置参数。

[Warning] Pre_HBNC.m:45 — 硬编码阈值 5
------------------------------------------------------------------------
问题描述：if sum(target_label_other)>5 — 魔法数字 5 决定何时将剩余样本归入当前簇而非创建新簇。
修正建议：在注释中说明阈值含义，或提取为参数。

[Warning] Pre_HBNC.m / Impro_HBNC.m / Pro_Out.m — 缺少输入校验
------------------------------------------------------------------------
问题描述：这三个函数不检查 X0 是否包含 NaN/Inf，不检查维度，不检查 label_pre 的合法性。
影响：非法输入可能导致静默错误传播。
修正建议：在函数入口添加基本的输入校验。

[Info] EProjSimplex_new.m:31 — 最大迭代次数硬编码

[Info] algo_qp.m:57-63 — pinv 可能掩盖秩亏问题

[Critical] biclr_best_split.m:118 — BIC 惩罚公式与文档不一致
------------------------------------------------------------------------
文档规定（CLAUDE.md 7.4）：lambdaBIC * (d + 1) * log(nC)
代码实现：options.lambdaBIC * (d + 1) * log(max(n, 2))
差异：代码使用 max(n, 2) 保护 log(0)，文档直接使用 log(nC)。当 n=1 时，log(max(1,2)) = log(2) ≈ 0.693，
     而文档定义 log(1) = 0。
影响：在 n=1 的极端情况下惩罚不为零，与文档语义不同。虽然 n=1 节点已被 minNodeSize 拦截，但公式仍与文档不严格一致。
修正建议：若确认 n 始终 >= 2（受 minNodeSize 保护），可直接使用 log(n)；否则需在文档中说明 max(n,2) 保护的必要性。

[Critical] BIC_LR_HBNC.m:162 / demo_biclr.m:17 — epsVar 默认值与文档不一致
------------------------------------------------------------------------
文档规定（CLAUDE.md 7.2, 11.2）：params.epsVar = 1e-12
代码实现：默认 epsVar = 1e-8
差异：数值保护阈值差 4 个数量级。1e-8 比 1e-12 更宽松，可能掩盖本应检测到的细微结构。
修正建议：将默认值改为 1e-12 以与文档一致，或在文档中说明选择 1e-8 的理由。

[Warning] biclr_select_target_view.m:40 — 基准视图选择策略说明
------------------------------------------------------------------------
文档规定（CLAUDE.md 9.2）：b = argmin_v q_v，其中 q_v 为簇内平方误差
代码实现：[~, targetView] = max(unitGains)，选择 BIC 单位证据增益最大的视图
分析：qualityScores = -unitGains，unitGains 越大表示划分统计证据越强。这等价于选择"质量分最小"的视图，
     与 min(q_v) 在语义上一致。但具体数值计算方式不同（BIC 增益 vs 纯 SSE）。
结论：设计意图一致，评价指标不同。demo_biclr.m:53 的注释已说明。
修正建议：在 CLAUDE.md 中补充说明 BIC-LR 路径使用 BIC 增益而非纯 SSE 作为质量指标。

[Warning] algo_qp.m:37 — mapstd 标准化未在文档中说明
------------------------------------------------------------------------
问题描述：X{i} = mapstd(X{i}',0,1); 将数据标准化为零均值单位方差。这改变了数据尺度，
         但 theta（锚点）仍使用原始尺度初始化为 A{i}。
影响：algo_qp 内部 A/Z 优化在标准化空间进行，但初始锚点来自原始空间。后续优化会适应，但初始化阶段存在尺度不匹配。
修正建议：在 CLAUDE.md 或代码注释中说明 algo_qp 内部会执行标准化。

[Info] demo_biclr.m 默认 summaryMode 为 'bestACC'
------------------------------------------------------------------------
demo_biclr.m:26 设置 summaryMode = 'bestACC'，返回 ACC 最高那次运行的指标。
build_biclr_refined_config.m:105 也使用 'bestACC'。
这与"均值±标准差"报告模式不同，但不违反文档要求。建议在实验记录中明确标注汇总模式。

biclr_best_split.m:99-116 — 批量候选切分计算
------------------------------------------------------------------------
原始逻辑：对每个候选切分位置分别计算左/右子节点 SSE
向量化实现：使用 cumsum 计算前缀和/前缀平方和，一次性算出所有候选的 W1/W2
语义等价性：W1 = sqLeft - sum(sumLeft.^2, 2) ./ n1 代数等价于 sum_i ||x_i - mu||^2
数值保护：W1 = max(real(W1), 0);
边界情况：n1 = candidatePos(:) 已通过 minNodeSize 保证 n1 > 0
结果：PASS

注意：需要 Parallel Computing Toolbox
